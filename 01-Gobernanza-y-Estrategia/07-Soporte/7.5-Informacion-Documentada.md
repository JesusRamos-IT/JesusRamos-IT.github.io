# 📋 7.5: Información Documentada

> **Etiqueta ISO:** #Soporte #ControlDocumental #Versiones #SGSI | **Dominio:** Operativo

## 1. 🎯 Propósito del Control
Asegurar que la información documentada requerida por la norma ISO 27001 (y la necesaria para el funcionamiento del SGSI) esté disponible, sea adecuada para su uso, esté protegida contra pérdida de confidencialidad o uso inadecuado, y se controle su versión.

---

## 2. 📑 Evidencias Objetivas (¿Qué solicitar?)
*   **Procedimiento de Control Documental:** Documento que explica cómo se crean, revisan, aprueban y actualizan los documentos.
*   **Control de Versiones:** Registro o historial que muestre los cambios realizados.
*   **Acceso y Distribución:** Evidencia de quién tiene acceso a qué documentos.

---

## 3. ⚙️ Puntos de Verificación (Checklist de Auditoría ISO 19011)
1.  **¿Hay identificación?** ¿Cada documento tiene título, fecha, autor y versión?
2.  **¿Hay control de cambios?** ¿Si alguien edita una política o un procedimiento, queda registrado quién lo hizo y qué cambió?
3.  **¿Está protegida?** ¿Los documentos sensibles (ej. matriz de riesgos, contraseñas, configuraciones de red) están protegidos contra acceso no autorizado?
4.  **¿Es accesible?** ¿Los empleados que necesitan el documento pueden encontrarlo fácilmente?

---

## 4. ⚖️ Matriz de Criterio (Hallazgos y NC)

| Estado Encontrado | Clasificación | Acción Correctiva Esperada |
| :--- | :---: | :--- |
| **Ausencia de control:** Documentos dispersos, sin versiones, sin saber cuál es el vigente. | 🚨 **NC Mayor** | Establecer un repositorio centralizado (ej. Git) con control de versiones. |
| **Información desactualizada:** Se siguen usando procedimientos obsoletos que ya no aplican. | ⚠️ **NC Menor** | Revisión y archivo/destrucción de documentos obsoletos. |
| Documentos no protegidos: Información sensible accesible a cualquiera sin privilegios. | 🚨 **NC Mayor** | Aplicar controles de acceso (permisos de sistema/carpeta). |

---

## 5. Control Documental (Tu realidad técnica)
*Cómo gestionas la documentación bajo tu enfoque "Ninja Mode":*

*   **Repositorio Central (Single Source of Truth):**
    *   Todo el SGSI reside en un repositorio de **GitHub** personal[cite: 1].
*   **Control de Versiones:**
    *   Se utiliza **Git** para la gestión de versiones[cite: 1]. Cada `commit` actúa como una evidencia de trazabilidad (quién, cuándo y qué cambió).
*   **Disponibilidad y Accesibilidad:**
    *   Estructura de carpetas jerárquica para separar Gobernanza, Controles Anexo A y Evidencias Técnicas[cite: 1].
*   **Seguridad de la Información Documentada:**
    *   El repositorio actúa como el sistema principal de documentación técnica bajo el estándar ISO 27001:2022[cite: 1].
    *   *Nota:* Para documentos con datos sensibles (ej. IPs reales, contraseñas), se aplican controles de acceso y no se exponen al repositorio público (o se usan `.gitignore` para archivos de configuración sensibles).
