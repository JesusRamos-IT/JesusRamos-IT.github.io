# 📋 4.4: Sistema de Gestión de Seguridad de la Información (SGSI)

> **Etiqueta ISO:** #Gobernanza #Sistema #Procesos | **Dominio:** Organizativo

## 1. 🎯 Propósito del Control
Establecer, implementar, mantener y mejorar continuamente el SGSI. El requisito fundamental aquí no es tener "papeles", sino demostrar que existen **procesos** y que estos procesos **interactúan** entre sí (el modelo de ciclo PDCA: Planificar, Hacer, Verificar, Actuar).

---

## 2. 📑 Evidencias Objetivas (¿Qué solicitar?)
* **Mapa de Procesos:** Diagrama o lista que muestra cómo los procesos del SGSI (ej. gestión de riesgos, auditoría, RRHH, IT) interactúan.
* **Documentación de Procesos:** Los SOPs (procedimientos) que definen entradas, salidas, responsables y recursos necesarios.
* **Evidencia de Mejora Continua:** Actas que demuestren que el sistema se revisa y ajusta (no es estático).

---

## 3. ⚙️ Puntos de Verificación (Checklist de Auditoría ISO 19011)
1.  **¿Es un sistema?** ¿Los procesos están aislados o hay un flujo de información entre ellos? (Ej: ¿El resultado de una auditoría dispara una gestión de riesgos?).
2.  **¿Están definidos los recursos?** ¿Tiene el sistema los recursos necesarios (tecnológicos, humanos) para operar?
3.  **¿Se ha establecido la mejora continua?** ¿Hay evidencia de que el sistema ha cambiado/mejorado en función de los hallazgos?
4.  **¿Responsabilidades claras?** ¿Quién es el dueño de cada proceso dentro del sistema?

---

## 4. ⚖️ Matriz de Criterio (Hallazgos y NC)

| Estado Encontrado | Clasificación | Acción Correctiva Esperada |
| :--- | :---: | :--- |
| **Ausencia de mapa de procesos:** Documentación aislada sin conexión lógica entre sí. | 🚨 **NC Mayor** | Elaboración de un Mapa de Procesos y matriz de interacción. |
| **Procesos no implantados:** Existe documentación ("en papel"), pero en la práctica no se siguen. | 🚨 **NC Mayor** | Auditoría operativa para identificar desviaciones y re-capacitación. |
| Se definen procesos pero faltan responsables claros o recursos asociados. | ⚠️ **NC Menor** | Asignación formal de roles y recursos en los procedimientos afectados. |

---

## 5. Definición del Sistema (Tu realidad técnica)
*Espacio para mapear cómo interactúan tus procesos actuales:*

* **Procesos Principales:**
    * *Gestión de Infraestructura:* (Patching, Hardening, Backup).
    * *Gestión de Incidentes:* (Monitorización Wazuh, respuesta ante alertas).
    * *Gestión de Cambios:* (Modificaciones en GPOs o configuraciones de red).
* **Interacciones Clave (El "Sistema"):**
    * Cuando el proceso de **Monitorización (Wazuh)** detecta una anomalía -> Dispara el **Proceso de Incidentes** -> Que requiere una **Acción Correctiva (NC)** -> Que alimenta la **Revisión por Dirección**.
* **Mejora Continua:**
    * Revisión de logs de auditoría (semanal).
    * Reunión de balance de seguridad (trimestral).
